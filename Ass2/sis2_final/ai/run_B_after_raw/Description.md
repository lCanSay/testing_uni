# Test cases: Toolshop v5.0 (https://practicesoftwaretesting.com)

Every test creates its own data (fresh user via `POST /users/register`, random strong password). Seeded accounts are never used.

| ID | Title | Preconditions | Steps | Expected result |
|----|-------|---------------|-------|-----------------|
| SETUP | Create session user, store signed-in state | None | 1. Register a fresh user through the API. 2. Open `/auth/login`, log in. 3. Save storageState. | Account page (`page-title` = "My account") is shown; state saved to `.auth/user.json` for the `authenticated` project. |
| TC-REG-01 | Register a new customer | Unique email and random strong password generated. Anonymous visitor. | 1. Open `/auth/register`. 2. Fill first-name, last-name, dob (YYYY-MM-DD), country, postal_code, house_number, street, city, state, phone, email, password. 3. Click `register-submit`. 4. On the login page, log in with the same email and password. | After step 3 the browser is on `/auth/login`. After step 4 the account page opens with title "My account" (proves the account exists). |
| TC-LOG-01 | Login with valid credentials | Fresh user created via API. | 1. Open `/auth/login`. 2. Enter email and password. 3. Click `login-submit`. | URL contains `/account`; `page-title` = "My account". |
| TC-LOG-02 | Login with wrong password | Fresh user created via API (only one failed attempt is made, lock-out is at 3). | 1. Open `/auth/login`. 2. Enter the user's email and a random different password. 3. Click `login-submit`. | `login-error` contains "Invalid email or password"; URL stays on `/auth/login`. |
| TC-LOG-03 | Login with unknown email | None. | 1. Open `/auth/login`. 2. Enter a never-registered email and a random password. 3. Click `login-submit`. | `login-error` contains "Invalid email or password"; URL stays on `/auth/login`. |
| TC-BUY-01 | Buy 3 units of a product | Signed in through storageState (SETUP user). One in-stock, non-rental product chosen from `GET /products`. | 1. Open `/product/{id}`; read `product-name`, `unit-price`. 2. Set `quantity` = 3, click `add-to-cart`, wait for the toast. 3. Open the cart (`/checkout`). 4. Click `proceed-1`. 5. Click `proceed-2`. 6. Fill the billing address (incl. house_number), click `proceed-3`. 7. Select payment method "cash-on-delivery", click `finish`. | Cart contains only this product (`product-title`); `product-quantity` = 3; `line-price` = unit price x 3; `payment-success-message` contains "Payment was successful". |
| TC-CMP-01 | Compare two products | Two different in-stock products chosen from `GET /products`. Anonymous. | 1. Open product A, read name and price, click `add-to-compare`. 2. Open product B, read name and price, click `add-to-compare`. 3. Click `compare-link`. | URL contains `/comparison`; `comparison-table` is visible and contains both product names; the `compare-price` values equal the two prices read from the product pages. |
| TC-PWD-01 | Reset password, known email | Fresh user created via API. | 1. Open `/auth/forgot-password`. 2. Enter the user's email, click `forgot-password-submit`. 3. Open `/auth/login`, log in with the ORIGINAL password. | Step 2: success alert is shown. Step 3: `login-error` is shown (old password no longer valid). |
| TC-PWD-02 | Reset password, unknown email | Fresh user created via API (control account). | 1. Open `/auth/forgot-password`. 2. Enter a never-registered email, click `forgot-password-submit`, wait for the response. 3. Log in with the control user's original credentials. | No success alert is shown. The control user still logs in (account page opens). |
